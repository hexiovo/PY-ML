# 零基础主试操作卡生成规则

此参考是给技能执行者的规则模板，不是某个研究的完成操作卡。每个具体研究都要生成一份与实际文件名、参数、命令、预期输出和错误处理相符的 operator.md；将以下尖括号占位替换为真实路径并在目标环境实测，交付主试的版本不得留下占位符。不要让主试修改 Python 代码、选择检验或猜阈值。研究人员需要做的决定要在方案开始前问清；计算机提示错误时，主试只需保存提示和日志。

## 操作卡必须包含

- 使用者需要准备的准确输入文件、文件位置、工作表/编码/分隔符及其不可修改的原始副本。
- 输出目录用途、预计生成的文件和已存在文件时的处理规则。
- 运行环境要求、经过核实的 Python 解释器路径、所需依赖及安装依据。没有验证过的安装命令应标为未运行。
- 每一步的完整复制命令、工作目录、脚本读取和写入哪些文件、成功后应看到什么。
- 可选动作与不可跳过的决策点，例如查看数据准备报告、审核配置、决定是否开始最终 test。
- 出错时要停止在哪一步、保留哪些文件、复制哪段报错给研究团队；不可指示主试通过重试来获得更好分数。

每条命令应在目标系统上实际执行成功后，才能标为已验证。命令执行环境、日期、版本、退出码和关键输出应记录。任何用用户真实文件验证的动作都需按请求范围进行，不要在“生成配置”请求中自动拟合或评估 test。

## 推荐操作次序

### A. 核对材料

先将原始数据放到用户指定的输入目录，设为只读副本，并将所有脚本、配置、临时文件和结果放到一个新建运行目录。打印路径与文件名供研究人员核对；不要覆盖已有输出。检查数据来源、单位、ID、目标及变量字典。

成功标志：操作卡显示输入输出路径，预期的每行含义与主试确认一致。  
失败处理：路径、列或单位不确定就停止，记录缺失项并联系研究团队；不要自行重命名或改数据。

### B. 核对当前软件

在目标项目环境运行：

    python -X utf8 -B "<技能包路径>/scripts/inspect_contract.py" --project "<PYML 项目绝对路径>" --output "<运行目录>/contract.json"

确认输出报告的 module_file 位于所选项目的 src/pyml_workbench 下，版本、模型项和参数 schema 均来自当前项目。若指向 site-packages、依赖缺失或报告 NOT VERIFIED，先让维护者解决；不要按旧快照继续声称配置可执行。

### C. 检查配置

只向 check_bundle.py 提供 experiment.json 和可选 search.json：

    python -X utf8 -B "<技能包路径>/scripts/check_bundle.py" --project "<PYML 项目绝对路径>" --config "<运行目录>/experiment.json" --search "<运行目录>/search.json" --output "<运行目录>/config-check.json"

search.json 未创建时省略 --search。不要将 preprocessing.plan.json、statistics.plan.json、预处理脚本参数或研究报告键传给 PYML 配置检查器。

读取 config-check.json 的独立结果：严格 JSON 与字段、真实 API 解析、模型/参数支持、源文件存在与否、表头预览。检查通过仍不代表数据内容、转换脚本、研究设计或科学结论已经核实，也不代表模型已经运行。

成功标志：原生键无未知字段；模型与任务兼容；参数由当前模型 schema 支持；列头与用户已确认的列名一致；状态与报告只到 checker 实际证明的级别。  
失败处理：保存 JSON、checker 输出和包版本，停止后续拟合，向研究团队提供错误摘要。不要删除未知字段后继续，先判断它是写错位置还是研究需要的外部步骤。

### D. 生成转换数据（如需要）

当 preprocessing.plan.json 中存在启用步骤时，按生成的命令运行 prepare_data.py。确认输出文件写入新目录，输入未被改写，并检查数据准备报告中的行数、独立 ID 数、键关系、目标缺失、每类数量、缺失比例和输出列。对合并、reshape、量表评分、单位转换或窗口生成，至少核对若干已知记录的原始值到输出值。

成功标志：脚本退出码为 0，处理摘要与计划一致，行数/键/单位/目标关系可追溯。  
失败处理：保留原始数据和完整错误；不要用 Excel 手工修复生成表后继续。先修正数据计划/脚本并重新核验新的版本。

没有启用转换时，应明确声明输入文件直接作为 PYML source_path，并说明检查了哪些列/编码。

### E. 试运行训练与验证（仅在用户请求或批准时）

若要做小范围 pilot，使用生成的运行入口调用公开 Python API `prepare_experiment`，且只返回开发数据结果和审计摘要。普通留出或附加 `evaluation` 报告 train/validation 与逐折拟合范围；直接 `split.strategy="kfold"` 报告 OOF 预测和折结果。K-fold 会话没有最终拟合模型，`freeze_experiment` 会拒绝它；N01/N02 early-stopping 不支持这条兼容路径。必须报告实际划分、拟合行、预处理器 fit 范围、模型和警告。不要把 CV refit 或 `run_experiment`、`finalize_experiment` 当作配置检查；它们会冻结模型或进入最终 test。

成功标志：训练与验证完成；测试指标不存在；test_evaluation_count 为 0；群组/时间划分和折内拟合检查通过。  
失败处理：保存运行目录、命令、完整异常和来源文件哈希，标为 blocked 或 failed。不要重开相同 job 绕过错误或重新测同一 test。

### F. 审核并进行唯一最终评估

让研究负责人检查目标、排除条件、特征、模型、预处理、随机种子、主指标、统计计划以及实际开发数据结果。普通留出流程确认 train/validation；K-fold 流程确认 OOF 折结果及适用的选择方案。只有负责人确认该版本后，才按对应 API 路径执行开发集重拟合并进行唯一最终测试：K-fold 单任务需经 `pyml_workbench.cv_experiment.refit_cv_session` 得到冻结会话，之后才能调用 `evaluate_test`。测试失败或中断后不可把同一个会话/测试集作为新机会重测。

成功标志：最终 test 只运行一次；保留冻结配置哈希、测试审计、结果表和模型工件。  
失败处理：保留失败状态和证据，停止并说明新独立数据或其他研究决策需求。

### G. 最终统计与交付

按 statistics.plan.json 运行经合成和真实接口核实的 run_statistics.py。报告实际分析对象数、独立单位数、估计量、效应量、置信区间、统计量、p 值、前提、缺失处理、比较家族、校正、模型失败和输出文件。纯预测任务说明推断统计不适用的理由。把预测性能和推断统计分开陈列。

成功标志：报告数值从实际输出文件生成，失败和未执行项目可见；结果清单包含所有脚本、配置、数据来源与哈希。  
失败处理：将运行结果标 blocked/partial，说明缺失的文件或方法，不用空表、假值、预测分数或 CV 均值填充推断结果。
