# 数据到结果的计划

本文件帮助把研究设计拆成可执行、可追溯的步骤。数据转换不是越多越好；没有明确用途的转换设为 disabled，并记录原因。

## 1. 固定分析单位和数据来源

先写清楚一行代表什么、一个独立单位是谁、结果变量代表什么。重复观测可以是同一个参与者的多个试次，也可以是同一个设备或地点的多次记录；这决定数据整理、预测划分和统计方法。把这些身份列保留在审计数据中，但通常不作为预测特征。

为每个源文件记录：

- 文件名、位置、格式、工作表、编码、分隔符、小数点格式、行数和列名。
- 文件哈希或可验证的内容标识；保留源文件副本或只读来源。
- 记录粒度、候选主键、是否存在重复键、每张表的键关系。
- 数据生成过程、纳入范围、特殊缺失标记及其来源。

若存在多个表，先对键的唯一性做检查，再执行合并。声明并检查预期的关系，例如 one-to-one、one-to-many 或 many-to-one。合并前后分别记录行数、唯一独立单位数和重复键数；若出现未经计划的行膨胀、丢失或 ID 复用，停止处理并查明原因。不要用多对多合并把试次复制成伪独立观测。

## 2. 数据字典与准入规则

对每列记录：

- 原始列名、含义、类型、单位、合法范围或类别。
- 角色：目标、候选特征、ID、分组、时间、参考标签、排除列或追踪列。
- 特殊编码（例如 -999 是缺失还是合法值）、来源和转换规则。
- 已知、建议或待确认状态，以及选择该规则的依据。

在读入后检查列名唯一、键完整、目标缺失、类别范围、数值单位、异常值、组内顺序和纳入条件。PYML 的训练目标不能含缺失值；如果目标缺失，先明确是否排除、重新标注或采用其他研究设计，再由独立脚本处理。不能把数值缺失填补当作目标缺失处理。

对有序分类、量表、二元变量和名义变量分开定义。数值列的机器存储类型不能代替测量尺度。缺失、不可能值、检测下限和真正的零值要区分。

## 3. 先分区，再拟合学习型转换

所有输入特征的模型评估均遵循：

1. 根据研究单位和部署目标确定训练、验证、最终测试分区。
2. 只用训练部分估计均值、中位数、尺度、类别字典、分箱边界、特征筛选、降维基向量、目标编码和采样方案。
3. 将训练部分已拟合转换应用到验证部分；不得在验证部分重新估计转换参数。
4. 每个交叉验证折单独在该折训练行拟合转换，再将其应用到该折验证行。
5. 搜索模型和阈值只使用训练/验证信息。锁定选择后再按受支持的 PYML 流程处理最终测试部分。

类别/单位/语义转换如果是确定性、在研究设计外已知的映射（如固定单位换算），可以在分区前执行；必须仍然保留原始值、规则版本和转换来源。凡从当前数据估计出来的边界或统计量，均属于学习型转换，必须在训练分区或每个训练折内拟合。禁止全表预处理后再分折。

PYML 当前对普通表格数据将数值中位数填补和缩放、类别众数填补和 one-hot 编码放入模型训练流程；这些 fit 会随训练/折分区执行。原生配置还提供 PCA 兼容字段 `pca_components`，以及 `reduction_method` + `reduction_components`（方法含 PCA、TruncatedSVD、FastICA、GaussianRandomProjection、KernelPCA）；降维器在同一训练分区或训练折拟合，之后再应用到相应验证数据。该能力不是任意转换图，必须先按目标源码检查模型兼容限制。凡需 reshape、合并、单位换算、量表得分、滞后/差分、目标变换、目标编码或重采样等外部步骤，应由独立脚本输出新的 PYML 输入表，并验证 ID 与目标未错位。不要把可选 PCA 降维误写成普通全表预处理。

## 4. 选择正确的验证结构

对于普通分类/回归，PYML 的固定外层留出比例是 60/20/20；不可在配置中改成其他比例。`random` / `holdout` 随机划分中，分类按类别分层、回归按行随机。存在同一独立单位的重复记录时，选 group 划分并把整个单位放在一个分区。组比例按组近似，不保证精确行比例；目前至少需要五个非缺失组，且分类的每个分区都必须含全部类别。`time` split 按唯一且非缺失的时间值排序，未指定时间列时按源行顺序。

时间序列预测要按照真实可预测时点排序，训练在过去、验证和测试在更后的时间。普通表格时间划分要求唯一时间值；同一时间多条记录需要先按科学单位聚合或使用明确支持结构的方法。PYML 外层 group 和 time 两种 split 不能同时启用。交叉验证的 gap 只影响时间折评估，不能替代最终 holdout 的 purge/embargo 或处理重叠窗口。

同一人的重复试次若要评估对新人的泛化，按人分组留出；对新时间点预测，时间留出更合适；若研究对象同时有多人多次测量，单纯按行随机通常会夸大泛化能力。若设计需要未见机构、家庭等更高层级泛化，按实际部署单位分组。类别在某些分区缺失时，不可偷偷降级成行随机分割，须报告结构与样本限制并选择有科学依据的其他计划。

序列 HMM 和窗口模型使用 SequenceConfig/SequencePlan 表示组内顺序与窗口映射。它们不是普通 group split 的别名，当前配置要求这些模型的外层 `split.strategy` 为 `random` 或 `holdout`；组内顺序和窗口映射由序列计划处理。若研究问题要求对未见参与者或未来时间点泛化，需先验证该模型的序列划分是否符合设计；无法证明时应标 `blocked`，不能静默改成按行随机。

PYML 有两条不同的 K 折配置路径，预算不能混为一个“拟合次数”：

- `split.strategy="kfold"` 使用兼容的直接 K 折路径，`split.n_splits` 为 2–10，保留独立最终测试集。搜索的 `max_fits` 按候选数计数；每个候选的底层 estimator 仍会在多折上拟合，因此候选数不是实际 fit 调用总数。
- `evaluation={"folds": K, ...}` 将折验证附加到留出流程。`max_fits` 按每候选一次主拟合加 K 个验证折计数。折只使用 train+validation 开发集，test 保持封存；每折各自拟合预处理。

参数台账应标出采用哪条路径、折数、搜索上限口径、每候选大致拟合工作量，以及冻结后重拟合和最终测试是否另计。不要把两种路径都描述成“最多 50 次模型拟合”。

## 5. 特征、模型和搜索

只纳入在预测时点可获得且不会泄漏结果的信息。排除未来值、处理后定义的结局、结果编码副本、人工分组标签、样本 ID、源文件行号和由全体样本产生的统计量。对目标派生特征、窗口预测、类别权重、阈值或损失函数说明为何适用。

先选择一个与研究目标、输入尺度、样本量、可解释性和部署方式相符的模型。记录 model_id、真实参数名称、参数单位/取值范围和依据。不得从任意示例复制参数或搜索范围。使用当前参数 schema 解析；构造器报错、模型缺少关键能力或搜索范围不适用时，停下并改成可验证方案。

模型选择可以依赖训练/验证分数。网格或随机搜索只搜索预先声明的有效参数；每个搜索候选、交叉验证折和拟合预算应在执行前可见。根据目标把性能指标和推断分析分开报告。

## 6. 执行前交付清单

输出以下可审查材料：

1. 数据来源清单、变量字典、合并关系和质量规则。
2. preprocessing.plan.json：逐步说明输入列、输出列、参数、单位、顺序、是否拟合及其拟合范围、随机种子、反向变换、ID 保留、失败处理和来源。
3. prepare_data.py：按上述计划真实处理数据，保存新文件而不覆盖原始文件；检查行数、键唯一性、目标对齐、列名和数据类型。
4. experiment.json：只包含 PYML 原生配置字段。
5. 可选 search.json：只用于有合理依据的模型参数搜索。
6. statistics.plan.json 与 run_statistics.py：仅在需要推断时使用；纯预测任务则注明不适用原因。
7. operator.md：用主试理解的语言列出每个动作、成功时应看到什么、失败时保存哪段信息，以及可复制的准确命令。
8. results-manifest.json：记录程序/依赖版本、配置和脚本哈希、真实运行时间、输入输出路径、行数/样本量、数据拆分、统计结果文件及未验证事项。

## 7. 失败与恢复

每个转换对行数、键、ID、列、单位、有限值和顺序的失败条件必须预先列明。脚本遇到超出规则的值时，保留输入并停止，给出列名、行位置/稳定记录 ID 和规则；不得静默删除、替换为均值或产生空数据。

每次数据或分析产物保存到新的版本化目录。配置、源数据、转换代码或统计计划变更后，旧验证证据不自动适用。不要覆盖已冻结的最终模型选择或重新用同一个测试集挑参数。失败的最终测试保留为失败并说明，按研究计划判断是否需要新的独立数据，而不是重启同一测试。
