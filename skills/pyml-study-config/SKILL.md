# PYML 实验配置

本技能是供 AI 助手使用的工作指引。它帮助把实验设计转成可检查、可复现的文件和操作步骤，但不替研究者决定未知的科学事实，也不认证研究结论。

## 便携模板与匿名示例

[`assets/templates/README.md`](assets/templates/README.md) 提供匿名化完整APA示例、可填写的Word/Markdown报告模板、图表重绘脚本及数据、HyperEEG引用式原生结果转换程序和相对路径CMD入口。先核对README的支持契约与依赖，再复用模板；示例的维数、指标和PASS数不是新研究结果。

模板及Git提交不得携带个人绝对路径、用户名、真实运行编号、原始EEG、原生身份记录、日志或本机结果指针。CMD使用自身目录与可配置解释器；启动后选择输入、输出、插件、MATLAB和依赖目录，配置保存到用户选择的SKILL外工作目录。复制或同步前扫描文本、DOCX压缩包XML及PDF正文/元数据；来源以相对文件名、公开链接和无个人路径的版本/哈希记录。保留原始业务输出，不能通过删除历史结果来实现模板匿名化。运行期间的真实追溯路径仍可写到用户侧台账，不回写公共模板。

## 应交付的内容

按实验需要生成文件，并为每项结论说明来源、状态和实际检查结果：

- `experiment.json`：符合目标 PYML 源码当前 `ExperimentConfig` 契约的原生配置，包括当前支持且与模型兼容时的降维字段。
- `search.json`：仅在需要模型参数搜索时提供。
- 使用 HyperEEG/PYfNIRs 转换插件时，先读取 `references/plugins.md`，另交 `conversion.plan.json`、插件原生参数文件、执行与核验步骤和主试操作卡。插件程序单独获取。
- 使用 PYEDA EDA 转换插件时，先读取 `references/pyeda-conversion.md`，核对结果包清单、特征定义、身份键、窗口状态和 outcome 来源。转换产物必须写入新的运行目录，并同时保存 `feature_dictionary.json`、`valid_mask.csv`、`provenance.json`、`conversion.plan.json` 和 `batch_summary.json`。
- `preprocessing.plan.json` 和可运行的 `prepare_data.py`：需要整理形状、合并、单位换算、特征工程或其他 PYML 不支持的转换时提供。
- `statistics.plan.json` 和可运行的 `run_statistics.py`：研究问题要求推断统计时提供。纯预测任务可标记 `not_applicable`，并说明原因。
- 参数台账、主试操作指南和结果清单：记录输入来源、变量定义、参数、假设、版本、路径和检查结果。

原生配置只接受目标 API 明确定义的操作；外部计划中的字段不得直接传给原生配置解析器。对原生流程当前未覆盖的转换或推断分析，应分别保存计划和脚本。所需脚本尚未实现、定义输入输出契约并实际检查时，状态应为 `blocked`，不能用空计划声称可执行。

## 工作流程

1. 读取 `assets/intake.md`，提取已有信息，并将关键内容标为 `known`、`proposed` 或 `missing`。不要重复询问已明确提供的信息。
2. 读取 `references/pipeline.md` 和 `references/toolkit-contract.md`。契约快照只能辅助起草；实际配置必须依据目标环境中显式加载的当前源码和 API。
3. 把影响方案的缺口合并成一组简明问题。不得猜测参与者或分组 ID、独立统计单位、目标含义、单位、时间基准、合并键、重复测量结构或确认性比较家族。可逆的工程默认值可以建议，但要标为 `proposed` 并说明影响。
4. 建立变量字典和参数台账，覆盖输入、清理、转换、划分、搜索、统计和输出；记录取值、单位或类别、来源、状态、理由、拟合范围及验证方式。逐条记明模型搜索预算口径；`split.strategy="kfold"` 按候选数计数，`evaluation` 按每候选一次主拟合加折数计真实拟合预算。
5. 按 `references/transforms.md` 判断转换是否适合测量尺度和研究设计。来源为 HyperEEG/PYfNIRs 或用户要求转换插件时，先按 `references/plugins.md` 核对插件和输入契约、生成原生参数及操作卡。每个非原生转换都要有明确的输入输出、顺序、参数单位、拟合范围、ID 保留方式、失败处理和来源；需要时编写并在合成数据上检查独立脚本。
6. 明确任务属于预测、描述汇总还是推断分析。需要推断时遵循 `references/statistics.md`，并为所需统计生成独立计划与可运行脚本。预测指标和交叉验证折汇总不能代替推断检验。
7. 从实时源码契约生成原生配置，并按 `references/operator.md` 执行可用检查。`check_bundle.py` 只接收原生实验配置和可选的搜索配置，不接收预处理或统计计划。
8. 模型、特征和参数选择只使用开发数据。生成配置本身不授权全量分析，也不应读取最终测试结果。
9. 报告当前状态、实际执行过的命令及结果。未运行的步骤明确写为 `NOT RUN`，不要把计划写成执行证据。

## 一键程序与实时进度（必须）

- 交付给主试的一键转换、数据准备和批处理程序必须在实际启动窗口显示实时进度。打印“正在处理”后静默等待、只把子进程输出重定向到日志、只在聊天中汇报，均不满足此要求。

### PYEDA EDA 转换

先读 [PYEDA 转换参考](references/pyeda-conversion.md)，核对已完成结果包、特征字典、身份与窗口字段。公开示例 `examples/pyeda` 复用独立插件，生成合成结果包或处理用户选定的结果包，输出全部登记特征、分组键、有限值掩码和质控摘要。公共示例使用特征模式。

项目确需建模时，逐结局记录标签来源、任务类型、分类类别顺序或连续尺度，以及独立分组或时间依据。已有明确配置时沿用，存在影响科学结论的歧义时才确认。数据支持且用户要求多轮或全方法时，使用派生种子记录每轮配置，核对可选依赖并保留各项失败或不可用原因。全缺失特征应显式标记，按用户和模型契约决定保留策略。时序输入须核对事件时间、窗口可用时点和隔离单位。

- 默认使用固定UI窗口显示当前阶段、已用时间和预计剩余时间，原位置更新，不向下追加刷屏。没有UI条件时使用终端固定区域/清屏重绘；详细路径、逐项计数、成功/跳过/失败和调试信息保留在日志或可展开详情中，不占据主界面。标明百分比和时间估计对应当前步骤还是全流程。
- 预计剩余时间只能依据真实已处理量与耗时或注明来源的有效历史耗时计算，明确为估计并标明范围；启动、总量未知或有效速度不足时显示“正在估计”。不得伪造倒计时、承诺准确ETA，或把当前步骤ETA称为全流程剩余时间。总量未知时不编造百分比。MATLAB等外部进程启动、长文件读取、写盘及校验期间也须至少每5秒刷新状态/等待提示；取得真实计数后及时更新，通常节流为约每秒一次。
- 可隐藏后台子进程窗口，但必须通过进度文件、回调或标准输出将真实进度转发到主试可见窗口；每个处理分支（包括跳过、不支持与失败）均计入已处理量。保留可读日志和机器可读进度快照，失败/取消显示实际终态并保留部分输出及原因。
- 只有输出写入和必要验收结束才显示本轮完成。范围内完成、部分成功、未选择、不支持、失败、取消必须区分；不得把已完成计数或进度100%当作全部科学结果均可用。
- 交付前实际检查一次正常启动及长耗时阶段的可见更新，核对计数与最终摘要一致；同时验证失败终态不被报告成成功。进度修复不改变既定数据范围、数值处理、身份映射或模型/最终测试流程。

## 全数据与全特征范围（必须）

用户要求“全部数据/全部特征”时，默认保留所指定、已核实转换表中的全部记录与全部特征列，先报告各表实际行×列、缺失及来源。不得为了小规模接口测试擅自改为前8列、前N列、无缺失列、非恒定列或抽样记录；外层每方法10次并不授权缩减输入。高维导致不支持或资源不足时保留失败与原因，不通过偷偷缩减特征制造PASS。

明确“已转换的全部特征”和“上游所有原生产物”范围不同；转换插件尚未支持的产物不能声称已纳入。不同层次或来源表保持边界，不能将整段/片段叠加成独立被试。使用全部特征不等于禁止按既定科研协议划分训练/验证/测试，也不授权全表拟合学习型预处理后再划分。

保留原值和缺失掩码；填补、缩放和必要模型适配的拟合范围须记录。高维输入经过PCA等变为低维时，分别记录原输入列数、变换后维数、方法与范围。仅选若干列不是学习型降维。任何特征删减必须有明确理由、完整台账及已有用户授权，不能静默进行。

真实标签缺失时，全部真实特征可用于适用的无监督描述性分析；分类等仍需用户确认真实目标，或在已有授权下用显著隔离的合成夹具验证接口。合成特征维数匹配真实表不等于真实EEG分类。报告必须写明每项结果的数据来源、参与的实际特征数/记录数及尚未分析范围。

更改特征范围须另建冻结运行，保留旧8列运行、证据和报告，不迁移旧PASS。结果必须保存到独立文件后才能提交PASS，保存开发集指标、预测/分数/解释和真实降维坐标，避免事后需要重新拟合才能写报告。

用户明确要求在真实特征上“随便假定”二分类时，允许另外建立REAL_FEATURES_ARTIFICIAL_TARGET分支；必须明确人工0/1不是真实条件/生理状态，标签固定、来源可追溯，不读取特征值、不按效果选标签/种子。真实全部特征与人工目标分别记录来源，不再笼统标为“全部合成数据”或“真实科研分类”。已有确认的被试/会话身份必须用于适当分组，禁止为了得到AUC将重复记录跨分区。可在每个被试内预先平衡人工标签以检查接口，但需说明这是夹具构造，不是实验随机化。旧结果和旧目标不覆盖，另建冻结运行。分类指标与真实特征排序可以报告，但只解释人工目标下的接口行为；不赋予脑区/临床/实验条件意义。

## 大型原生产物与内存边界（必须）

- 识别引用式结果包与真实payload路径，不把索引/统计汇总当训练值。明确本轮所选特征范围；未选择与不支持分别记录，不能为节省内存偷偷丢特征或样本。
- 入口核验后复用有效schema与哈希，避免在内部循环重复等价扫描、加载或散列。每个MAT产物只载入一次并复用已解码对象；遍历下一产物前释放上一产物及临时引用。不得为了逐表导出再整份load同一MAT。
- 对大型/复杂MAT在load前做元数据层估算与内存准入，保留系统空闲内存；检查主进程与自建worker的合计预算。压缩文件长度不等于展开内存，MCOS/table仍可能完整原生解码。估算是保护启发式，不承诺任意对象峰值硬上界；估算不支持或预算不足时清楚停止，不能盲目回退整份读取。
- 源表逐表处理并及时写盘、释放DataFrame，原始表缓存默认不保留全批；只累计最终必要标量及轻量元数据，给最终输出的行×列/内存规模设置明确上限。不得并存全部逐文件对象、全部源表和重复合并副本。
- 内存/资源不足、输入损坏、I/O失败、身份/数值冲突均为失败，向外传播并保留错误和部分输出。只有已明确识别的“不支持格式/列布局”可记录为不支持；不可用宽泛catch吞掉MemoryError/OutOfMemory/预算拒绝，伪装成部分成功。
- 仅修改数据格式或读取策略时，保留身份、数值、缺失与范围；用适当的差分/已知值核对，不重新计算科研特征或统计结果来验证界面。进程树峰值只能按真实采样报告，写明基线、采样间隔和共享页/漏短峰等限制；没有测量不能声称峰值降低比例或整套问题彻底解决。
- 所有程序输出与运行记录使用用户指定目录，每轮新建子目录。将程序、结果、日志的具体落点写入操作卡；不能默认写到代码delivery目录或把旧路径说成已迁移。

## 主包全方法测试实例与PASS接续（必须）

当用户明确要求主包“一站式实例”“全部方法覆盖”或小规模接口测试时，先区分接口测试与真实科研评估；按目标环境实际catalog/API冻结覆盖清单，不能把模型数、构造器解析或方法名出现称为拟合通过。方法覆盖以主包当前模型清单为基础，相关搜索/训练前降维按用户范围补充；未实现、依赖缺失或输入不支持也必须留在清单，不能删除以制造全PASS。

- 明确外层重复次数的口径。用户指定每方法10次时，每个方法有10个独立测试槽位，固定小规模参数与预先声明的种子，不做全参数网格或按最好结果挑种子。外层10次不等于模型max_iter=10、10折交叉验证或总fit调用10次；TSNE最小迭代数、LDA受类别数限制的n_components、深度epoch和搜索候选数必须服从实际接口并写明。CatBoost等同义参数只选一个规范名称，不能同时设置iterations与n_estimators；退火搜索须有真实连续变量，不能把仅choice的空间强行套用。
- 真实目标/主体/时间结构缺失时不伪造科研标签。只有用户明确允许合成测试夹具时才建立独立、显著命名的SYNTHETIC数据；其标签、组ID和时间只属于夹具，不当作真实EEG事实。真实无标签数据可用于无监督全量描述性接口拟合，保持来源表分开，不声称独立验证或新被试泛化。
- 需要训练流程检查时使用真实公开API，例如prepare_experiment及主包的适配/预处理/搜索接口；明确不调用run_experiment、finalize_experiment或evaluate_test来做烟雾检查。正常结束须断言test_evaluation_count为0且无最终test输出；内部训练/验证指标不用于性能排名或科研结论。
- 方法PASS必须来自实际fit及其正确任务输出/必要不变量。HMM可能只返回训练/验证似然而不返回逐行rows，应核对真实EM执行、有限似然、序列边界和受支持推断；不能统一要求所有方法都具有相同输出API。无监督不支持新数据predict/transform时不能偷偷重拟合代替。
- 按“方法ID/重复编号”做最小接续单元。stages.json只保存阶段键到true/false的PASS映射，true仅在完整执行和检查后原子提交；false表示未通过，未出现的键表示尚未提交PASS（尚未执行或执行中断）。错误、警告、冻结配置、数据来源与版本分别存放，不能把失败写成PASS或把未执行伪装成已失败拟合。
- 同一冻结运行重启时只跳过有效true项，false/缺失项可重新执行。单次fit/epoch中断只能从该未PASS循环重新开始，不能声称恢复到任意模型内部训练点。此接续机制只针对工程接口测试，不能用来绕过真实研究最终test的失败/中断限制。
- 接续前在最外层检查输入快照、协议/参数、解释器、依赖版本、主包源码和实例代码指纹；变化时拒绝直接复用旧PASS并显式建立新运行或经审阅失效受影响证据。内部循环不重复全量输入扫描或哈希。
- 逐方法隔离可选依赖和训练资源，最多一个模型worker，限制主进程+worker合计内存和运行时间；及时释放上一模型。实际失败、资源拒绝和依赖缺失保留具体原因，不为全PASS静默降级或移除方法。
- 实例必须完整交付：一键入口/固定UI、可复制CLI、冻结设置与方法/参数/数据清单、严格PASS状态、独立错误日志、结果摘要、操作与接续说明、已执行验证证据。验证至少覆盖代表任务真实调用、PASS跳过接续、输入/代码变化拒绝接续、失败状态不被记为PASS；不重复已通过且未受影响的等价检查。

## 全任务未来模板与模型对比图（必须）

用户要求全部方法作为未来模板时，不能只做0/1分类。按实时catalog为二分类、多分类、连续回归、正计数/分布受限回归、窗口序列回归、单序列预测及其他适用任务建立目标字典、可执行配置、实际拟合和任务特定输出检查；无因变量的方法仍按其真实契约执行，不硬塞标签。每流程重复10次时写清“方法×目标类型×数据表×重复”的数量，不能以构造器解析或目录名覆盖代替拟合。

- 真实目标缺失而用户授权假定时，可建立独立且明确标记的人工二/多分类、正连续、正整数目标；固定生成规则与种子，不根据特征或预测效果挑标签。人工顺序/时间或符号也必须显著标注为测试夹具，不冒充真实时序或观测。需要充分时序或特定输入域的方法可使用已获授权的独立合成夹具，并明确真实/人工、样本数、特征数与适用范围。
- 输入全量不等于每个算法都能使用全部列：例如单变量预测适配器只读取目标历史，类别HMM要求离散符号。保留原始数据，按算法契约明确例外及原因；不可假称模型消费了696维EEG外生输入，也不能静默改成前8列。
- 分类报告必须同时交付逐模型accuracy和AUC表格、实际绘制并嵌入的对比图，必要时按二分类/多分类和数据表分面分页，统一范围、类别顺序和比较口径。二分类正类与多分类OvR/OvO、macro/weighted写明；失败/不可估计模型在表和图的清单中保留。图通常用均值点及明确标注的SD/有效区间，不只放表、ROC或PASS图来代替模型间对比。
- 回归至少交付MAE/RMSE/R²等适用指标及跨模型对比图、预测—真实值或残差图；计数/分布型任务注明目标域及适用偏差指标。序列/预测保留窗口、步长、顺序、边界和适用时间图。评估样本不足导致R²/AUC等未定义时写明原因，不填0或把工程失败吞为成功。
- 有限预测及接口PASS不代表拟合质量合格。极小迭代预算下出现巨大误差/极负R²时，保留原值与警告，明确数值或优化失稳；表用科学计数法，图必要时用显著注明的对数/对称对数刻度，不截尾、隐藏失败或把SD当作合法取值界限。表格须在渲染后检查长数字是否挤坏列宽。
- 区分程序缺陷、接口缺能力、参数与数据条件不匹配、资源拒绝、数值未收敛及不可估计指标。纯PASS文件外提供error_category/reason和诊断证据；不要把所有情况统称“程序错误”或“数据问题”。模板应预先选择有依据且可审阅的兼容配置，如高维QDA的显式协方差收缩、RANSAC与训练样本匹配的min_samples，而非靠删特征或泄漏分区让它通过。
- HMM在极少观测、高维或未充分访问隐状态时可能出现转移概率行和为0、非有限EM参数或似然。保存该数值退化及实际种子/维数，不强行补概率或反复挑种子；若另用独立、已授权的合成发射夹具，只能作为接口例，不能说真实数据已通过。
- 需要堆叠时，内层OOF和成员预处理也必须尊重已确认的被试组。原生接口不支持则明确不适用；若实现支持，保留分组内折审计，实测分类与回归，并保留普通非分组路径兼容性。接口扩展或参数修复需新建冻结运行，不复写历史PASS或把新配置的数值归为旧运行。
- 一站式程序应交付所有目标类型的结果、完整方法差异清单、可运行入口、固定UI、阶段布尔PASS、错误分类、数值与图表数据、报告生成程序和已执行证据。运行结束的报告必须逐任务列方法与结果，不能只写分类或只列覆盖数量。

## 运行结束后的 APA 报告（必须）

EDA 写作经验见[报告复盘](references/reporting.md#eda-报告复盘)，包括分区与基线、样本流转、类别识别及图表核验。

用户在运行结束后提供结果文件夹并要求报告时，使用本技能的 `references/reporting.md` 完成目录核查、实验设计对应、真实引用核验和报告交付。默认中文、APA 第 7 版稿件结构，包含题名页、摘要与关键词、引言、方法、结果、讨论、参考文献及必要的字母编号附录，交付可编辑 DOCX 及结果来源台账。作者、机构或通讯信息缺失时标为待补。报告围绕实际研究问题、条件、独立单位与重复测量结构。

报告必须使用清晰的主章节与子章节，按实际任务/算法家族解释差异，并用逐算法比较表或附录覆盖本次全部方法，写明机制、假设、参数、输入输出、适用条件、实验关联及执行状态。必须实际绘制并嵌入来源可追溯的图表，提供图表数据与可运行绘图脚本，检查 APA 图表标注和渲染效果；接口测试绘制执行状态等工程图，不能据合成分数制作科研性能排行榜。

报告正文应遵循“正文简洁、附录完整”的分流。正文只展示研究问题、样本流、核心结果、关键图和必要解释；逐方法、逐 outcome、逐迭代的长表、全部参数、全部指标、失败原因和 catalog 机制放入附录及机器可读表，不把过长表格挤在正文中。附录必须能追溯到本轮冻结结果，不能只给摘要或最佳模型。

APA 第 7 版默认正文双倍行距，按用户指定可用 1.5 倍。拉丁字符使用 Times New Roman，中文正文使用宋体，标题和小标题使用黑体并加粗，文字颜色为黑色，页边距 2.54 cm。页码置于右上角，图表编号加粗、标题斜体、注释置于下方，参考文献使用 1.27 cm 悬挂缩进，附录图表使用字母与数字编号。DOCX、PDF 和 Markdown 的章节、图表编号与附录名称保持一致。

PYEDA 报告正文使用 13 磅，主标题 17 磅，表格、图注及图内文字在实际插入尺寸下至少 11 磅。图表采用可读的中文标签、明确的指标方向和参照线，正文逐图说明读法及发现。模型多时拆图或分页，完整结果放附录。分类同时展示类别分布、基线、平衡准确率、ROC-AUC 和带行比例及计数的混淆矩阵。回归区分汇总表和窗口数据，标明测试集、有效观测数及轮次汇总方式。仅调整报告时，从已保存的结果重绘和排版。交付前按最终页面尺寸渲染检查，核对字体、图注、坐标、跨页和数值。

说明指标的优先级时，从研究问题出发。二分类优先解释研究所关注类别的召回率、精确率、平衡准确率、AP 与同轮正类比例、ROC-AUC。保留梯形 PR-AUC 并说明它与 AP 的计算区别。将 F1、MCC、κ、准确率及概率误差用于补充解释。回归并列报告 R²、MAE、RMSE 和训练、验证、测试差异。逐轮记录有效样本量、均值、波动范围和不可估计原因。特征重要性另报评分函数、验证集、置换单位、轮次及变化方向。事件分类特征在参与者 × 任务内重复时，按任务置换整组参与者特征向量，保留同一向量与多条回答的对应关系。

扩充 PYEDA 讨论时，依据冻结结果解释匹配覆盖与选择性缺失、结局定义与信度、特征的时间分辨率、指标间的权衡，以及团队或被试切分允许的外推范围。源事件与模型表可追溯时，按任务核对标签、匹配损失、类比例，以及输入相同但包含两类标签的被试–任务组合。已保存训练目标和测试预测时，可按原切分做描述性误差比较，MAE 使用训练中位数，RMSE 使用训练均值。逐轮保存分母、来源与哈希，保持冻结模型与预先确定的展示规则。

只要结果目录包含对应输出，就报告全部适用核心指标和定义。回归至少包括有效样本数、R²、MAE、MSE、median absolute error、pinball loss、RMSE、MAPE、MSLE、RMSLE、SMAPE、MASE 及适用的 pinball quantile。分类包括有效样本数、accuracy、balanced accuracy、precision、recall、F1、MCC、Cohen’s kappa、ROC-AUC、average precision、PR-AUC、log loss、Brier score、类别顺序、正类、混淆矩阵和不可估计原因。AUC 不得用于没有真实分类标签的结果，也不得用 PASS 数或类别预测替代连续分数。

关键指标必须有对应图或图表面板。回归至少提供 R²、MAE、RMSE 的跨模型图，必要时提供预测—真实值图和残差图。分类至少提供 accuracy/AUC 对比图和适用的 ROC、PR 或混淆矩阵。极端值使用明确标注的科学计数法或对称对数尺度，不截断、不隐藏、不把收敛警告改写为正常结果。

报告“重要性程度”时必须写明口径。默认使用同一 outcome 内完成方法的描述性分位数等级，例如前 25%、中间 50% 和后 25%，并明确这不是统计显著性、因果重要性、特征重要性或总体泛化证明。没有预先定义或有效比较范围时写“不可分级”，不凭主观形容词排名。

报告必须列出所有核心模型参数。至少包括模型 ID、实现、算法家族、构造器参数、默认值或实际取值、随机种子、训练/验证/测试比例、group/time 策略、目标列、特征数、预处理拟合范围、模型状态和失败原因。逐槽位参数放附录，正文只保留影响解释的参数。

引用应覆盖实际使用的 EDA 方法、SCR/EDA 质量规范、评价指标、交叉验证、模型选择偏差和机器学习实现。引用数量服从论点需要，文内作者—年份与文末 APA 参考文献逐一对应，不能用未核实的 DOI、页码或搜索片段凑数。

结果必须包括实际保存且适用的预测指标（分类accuracy、AUC等）、分类输出和有定义的特征排序及图表，不能以PASS代替结果。每方法首次执行应保存指标/预测/类别分数/解释与数据分区；缺失时明确未保存，用户要求补算则另建有来源的开发集补充运行。单独报告降维是否实际执行、所用数据、维数与拟合范围。合成结果只能解释为夹具输出，不能解释为真实脑电效度。

正文采用自然、具体、克制的学术表达，删除空泛套话、机械衔接和重复总结；“去 AI 味”不代表隐藏不确定性、虚构亲历或规避检测。引用须真实、可核实且支持对应论点，文内作者—年份与文末 APA 参考文献一一对应。

读取结果不等于授权重跑模型或最终 test。缺少实验设计关键事实时先整理已知证据，再一次性询问必要缺口；未完成运行只出明确标注的部分报告。当前合成夹具和每方法 10 次循环只能支持接口验证报告，不能写成真实 EEG 科研发现；PASS 不是统计显著性或泛化证据。该规则是助手接收目录后的工作流程，不得宣称未实现的报告按钮已经存在。

## 状态定义

- `draft`：已有方案草稿，仍有重要设计选择未定。
- `blocked`：缺少必需事实、依赖、支持操作或验证，尚无安全可执行路径。
- `pending_real_data`：方案或合成示例已准备，尚未检查真实输入。
- `ready_for_pilot`：已检查真实输入的字段和基本约束，所需脚本也通过合成数据检查；仅表示可进行有界试运行，不代表科学设计已获认证，也不授权用最终测试结果选模。
- `ready_for_execution`：实际输入、配置、脚本、依赖、输出路径和操作步骤均已核实，且没有未解决的关键决策；表示可以开始执行，不表示已经运行。
- `completed`：请求的工作流已实际运行并产生真实输出；分别报告预测结果、推断结果、失败、局限和交付文件。

JSON 语法检查、API 解析、列预览或合成示例单独都不能使任务达到 `ready_for_execution`。报告应区分结构检查、输入预览、运行时解析、科学设计就绪情况和实际分析结果。

## 必须遵守的边界

- 不编造数据、单位、身份、抽样方式、假设、排除规则、独立统计单位或来源；明确区分已知、建议和缺失信息。
- 参与者、集群、站点、家庭、设备或会话 ID 默认不作模型特征，除非研究问题明确要求并解释其预测用途。训练、验证、测试和统计分析都要尊重真实独立单位。
- 同一独立单位的重复观测不得跨训练、验证和测试集合。未来预测按时间排序；不得打乱有时间依赖的数据。PYML 的 group 与 time 外层划分不能同时启用；交叉验证 gap 不等于最终留出集的 purge 或 embargo。
- 缺失值填补、缩放、编码、特征选择、PCA、目标编码、重采样等学习型转换只能在训练分区拟合，并在每个交叉验证训练折内重新拟合。禁止先处理整张表再随机划分；SMOTE 等重采样不得作用于验证或测试数据。
- PYML 有受限的原生训练前降维配置；先核实模型和当前源码是否支持。其余研究转换须由独立脚本承担，不能把 `preprocessing.plan.json` 或统计计划中的字段混入 `experiment.json`。
- 不把交叉验证折或同一集群的行当作独立统计样本；考虑配对、重复测量、聚类和时间依赖。不得只凭正态性检验的 p 值选择检验，也不得反复更换方法追逐显著性；需预先说明比较家族和多重比较处理。
- 只有当前 API 明确支持的操作才能写入原生配置。其余转换或研究推断分析应由独立、可审阅的脚本完成，定义输入输出契约、保留行与被试身份、用合成数据验证；无法完成并核实时标为 `blocked`。
- 最终测试只按已冻结的流程使用一次。失败或中断不是重新建任务、改种子重测的理由；如果测试结果已被查看后再改方案，应说明测试集污染及独立验证需求。
- 不虚构 GUI 按钮，也不把内部 worker 命令称为用户 CLI。只使用当前项目真实存在的界面或已核实的公开 Python API。
- 如果 AI 没有文件或运行工具，就提供完整文件正文和准确命令，标出未执行项；不得声称已达到 `ready_for_pilot`、`ready_for_execution` 或 `completed`。
