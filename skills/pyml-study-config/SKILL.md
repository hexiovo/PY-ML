# PYML 实验配置

本技能是供 AI 助手使用的工作指引。它帮助把实验设计转成可检查、可复现的文件和操作步骤，但不替研究者决定未知的科学事实，也不认证研究结论。

## 应交付的内容

按实验需要生成文件，并为每项结论说明来源、状态和实际检查结果：

- `experiment.json`：符合目标 PYML 源码当前 `ExperimentConfig` 契约的原生配置，包括当前支持且与模型兼容时的降维字段。
- `search.json`：仅在需要模型参数搜索时提供。
- `preprocessing.plan.json` 和可运行的 `prepare_data.py`：需要整理形状、合并、单位换算、特征工程或其他 PYML 不支持的转换时提供。
- `statistics.plan.json` 和可运行的 `run_statistics.py`：研究问题要求推断统计时提供。纯预测任务可标记 `not_applicable`，并说明原因。
- 参数台账、主试操作指南和结果清单：记录输入来源、变量定义、参数、假设、版本、路径和检查结果。

原生配置只接受目标 API 明确定义的操作；外部计划中的字段不得直接传给原生配置解析器。对原生流程当前未覆盖的转换或推断分析，应分别保存计划和脚本。所需脚本尚未实现、定义输入输出契约并实际检查时，状态应为 `blocked`，不能用空计划声称可执行。

## 工作流程

1. 读取 `assets/intake.md`，提取已有信息，并将关键内容标为 `known`、`proposed` 或 `missing`。不要重复询问已明确提供的信息。
2. 读取 `references/pipeline.md` 和 `references/toolkit-contract.md`。契约快照只能辅助起草；实际配置必须依据目标环境中显式加载的当前源码和 API。
3. 把影响方案的缺口合并成一组简明问题。不得猜测参与者或分组 ID、独立统计单位、目标含义、单位、时间基准、合并键、重复测量结构或确认性比较家族。可逆的工程默认值可以建议，但要标为 `proposed` 并说明影响。
4. 建立变量字典和参数台账，覆盖输入、清理、转换、划分、搜索、统计和输出；记录取值、单位或类别、来源、状态、理由、拟合范围及验证方式。逐条记明模型搜索预算口径；`split.strategy="kfold"` 按候选数计数，`evaluation` 按每候选一次主拟合加折数计真实拟合预算。
5. 按 `references/transforms.md` 判断转换是否适合测量尺度和研究设计。每个非原生转换都要有明确的输入输出、顺序、参数单位、拟合范围、ID 保留方式、失败处理和来源；需要时编写并在合成数据上检查独立脚本。
6. 明确任务属于预测、描述汇总还是推断分析。需要推断时遵循 `references/statistics.md`，并为所需统计生成独立计划与可运行脚本。预测指标和交叉验证折汇总不能代替推断检验。
7. 从实时源码契约生成原生配置，并按 `references/operator.md` 执行可用检查。`check_bundle.py` 只接收原生实验配置和可选的搜索配置，不接收预处理或统计计划。
8. 模型、特征和参数选择只使用开发数据。生成配置本身不授权全量分析，也不应读取最终测试结果。
9. 报告当前状态、实际执行过的命令及结果。未运行的步骤明确写为 `NOT RUN`，不要把计划写成执行证据。

## 状态定义

- `draft`：已有方案草稿，仍有重要设计选择未定。
- `blocked`：缺少必需事实、依赖、支持操作或验证，尚无安全可执行路径。
- `pending_real_data`：方案或合成示例已准备，尚未检查真实输入。
- `ready_for_pilot`：已检查真实输入的字段和基本约束，所需脚本也通过合成数据检查；仅表示可进行有界试运行，不代表科学设计已获认证，也不授权用最终测试结果选模。
- `ready_for_execution`：实际输入、配置、脚本、依赖、输出路径和操作步骤均已核实，且没有未解决的关键决策；表示可以开始执行，不表示已经运行。
- `completed`：请求的工作流已实际运行并产生真实输出；分别报告预测结果、推断结果、失败、局限和交付文件。

JSON 语法检查、API 解析、列预览或合成示例单独都不能使任务达到 `ready_for_execution`。报告应区分结构检查、输入预览、运行时解析、科学设计就绪情况和实际分析结果。

## 必须遵守的边界

- 不编造数据、单位、身份、抽样方式、假设、排除规则、独立统计单位或来源；明确区分已知、建议和缺失信息。
- 参与者、集群、站点、家庭、设备或会话 ID 默认不作模型特征，除非研究问题明确要求并解释其预测用途。训练、验证、测试和统计分析都要尊重真实独立单位。
- 同一独立单位的重复观测不得跨训练、验证和测试集合。未来预测按时间排序；不得打乱有时间依赖的数据。PYML 的 group 与 time 外层划分不能同时启用；交叉验证 gap 不等于最终留出集的 purge 或 embargo。
- 缺失值填补、缩放、编码、特征选择、PCA、目标编码、重采样等学习型转换只能在训练分区拟合，并在每个交叉验证训练折内重新拟合。禁止先处理整张表再随机划分；SMOTE 等重采样不得作用于验证或测试数据。
- PYML 有受限的原生训练前降维配置；先核实模型和当前源码是否支持。其余研究转换须由独立脚本承担，不能把 `preprocessing.plan.json` 或统计计划中的字段混入 `experiment.json`。
- 不把交叉验证折或同一集群的行当作独立统计样本；考虑配对、重复测量、聚类和时间依赖。不得只凭正态性检验的 p 值选择检验，也不得反复更换方法追逐显著性；需预先说明比较家族和多重比较处理。
- 只有当前 API 明确支持的操作才能写入原生配置。其余转换或研究推断分析应由独立、可审阅的脚本完成，定义输入输出契约、保留行与被试身份、用合成数据验证；无法完成并核实时标为 `blocked`。
- 最终测试只按已冻结的流程使用一次。失败或中断不是重新建任务、改种子重测的理由；如果测试结果已被查看后再改方案，应说明测试集污染及独立验证需求。
- 不虚构 GUI 按钮，也不把内部 worker 命令称为用户 CLI。只使用当前项目真实存在的界面或已核实的公开 Python API。
- 如果 AI 没有文件或运行工具，就提供完整文件正文和准确命令，标出未执行项；不得声称已达到 `ready_for_pilot`、`ready_for_execution` 或 `completed`。
