# 用户指南

完整工作流程见[操作指南](overall-guide.md)；主窗口底部“操作指南”按钮、帮助菜单或 F1 可打开应用内离线阅读窗口，支持章节跳转和搜索。

Windows 用户请从 [GitHub 最新 Release](https://github.com/hexiovo/PY-ML/releases/latest) 下载程序包，完整解压后运行 `Start.cmd`。也可使用 `Install.cmd` 安装到当前用户目录；无需另装 Python。部署说明见 [Windows 下载与安装](exe-guide.md)。

本指南介绍单任务训练、验证、最终测试、模型导出和新数据推理；多数据集搜索见[批量搜索指南](batch-guide.md)。当前模型目录有 111 个条目，功能和输入限制见[模型索引](model-index.md)。序列与深度学习任务的配置另见[序列建模指南](sequence-guide.md)和[深度学习指南](deep-learning-guide.md)。模型目录数量表示可选条目，不表示每个模型都支持相同操作或已对所有模型完成全流程拟合测试。

图表只使用当前完整表格或通过主应用核验的任务缓存。旧缓存缺少绘图清单时，不会据此重训或执行测试。

主窗口顶部可导入、保存修改或导出 JSON 参数设置。导入的配置通过校验后回填界面；“保存修改”写回当前绑定文件，“导出设置”另存副本。数据转换插件从“格式 → 数据转换 → 插件设置…”配置；缺少运行依赖时可在“帮助 → 检查运行环境…”中查看并使用“一键安装”。插件与依赖安装说明见[Windows 下载与安装](exe-guide.md)。

## 启动

在项目根目录完成依赖同步后，双击 `run_pyml_workbench.bat`，或在 PowerShell 运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pyml_workbench
```

启动器使用已有 `.venv`；如提示缺少虚拟环境，请先按 [README 安装步骤](../README.md#安装与启动)同步，不要把源码目录添加为 editable 安装。

## 日志、参数配置与最近文件

### 错误详情与日志目录

右侧“阶段日志”显示当前任务的进度；窗口底部的“复制错误详情”会把错误 ID 和 traceback 复制到剪贴板，反馈问题时可一并提供。应用诊断日志默认保存在 Windows 的 `%LOCALAPPDATA%\PyMLWorkbench\logs`。在“文件”菜单选择“选择日志目录…”可立即切换后续日志的保存位置；“恢复默认日志目录”会切回默认位置，已经写入旧目录的日志不会搬到新目录。若日志不可用，窗口会显示提示，工作流程仍可继续。

选择“文件”→“导出诊断包…”后，可导出“当前界面会话”，也可选择“按错误编号”并输入此前复制或保存的 32 位 `error_id`。接着选择 ZIP 的保存位置。导出内容按字段 allowlist 收集并脱敏，最大 20 MiB；程序只在本机创建文件，不会上传。任一步骤取消都不会创建 ZIP；无效或找不到的编号会显示提示；已有目标文件会受到保护，不会被覆盖。导出不会更改实验结果或日志目录设置。

### 保存和加载参数配置

主窗口顶部工具栏和“文件”菜单提供三项设置操作：

- **导入设置（Ctrl+O）**：选择 JSON 文件。配置通过校验后回填单任务界面；如果数据路径有效，工作台会载入数据预览。导入不会开始训练、搜索或最终测试。
- **保存修改（Ctrl+S）**：将更改写回当前绑定的设置文件。尚未绑定文件时，先选择保存位置。
- **导出设置（Ctrl+Shift+S）**：把当前配置另存为 JSON；导出副本不会更改当前绑定文件。

配置只记录实验参数和数据路径，不包含数据表或模型结果。保存或导出前检查数据文件、列选择和参数；不要用配置文件覆盖源数据或现有结果。

### 最近文件

成功加载的表格路径会按最近使用顺序保存在“文件”→“最近文件”中，最多记录 10 个路径。选择菜单项会重新加载对应文件；源文件已不存在时，菜单会标记并禁用该项。选择“清除最近文件记录”只会清除记忆的路径，不会删除表格或日志。

最近文件和日志目录属于应用偏好设置，与单次实验参数配置分开保存。Windows 默认偏好文件位于 `%APPDATA%\PY-ML\preferences.json`。

## 导入与预览

1. 在“数据与列选择”中点“选择文件”，选择 `.csv`、`.xlsx` 或 `.xls`，再点“加载预览”。预览会读取表格和少量示例行，不写回源文件。
2. Excel 文件可在“工作表”中选择工作表。CSV 没有工作表选择。
3. 勾选要用作输入的特征列。分类和回归需要在“目标列”选择标签/数值目标；聚类、降维和异常检测不使用目标列。目标列不能同时作为特征。
4. 检查预览、列类型和缺失情况。监督任务的目标值不能缺失；无效路径、重复列或不支持的文件格式会显示错误，修正输入后重新加载。

数据读取与预览不修改原表。训练结果应保存到单独的新目录；程序会拒绝覆盖输入文件或已有产物。

## 数据概况与基础图表

加载表格后，在主窗口“分析”菜单中选择“数据概况…”，查看完整数据的行列数、逐列类型与缺失数，以及 pandas `describe(include="all")` 描述统计。概况基于当前内存中的已加载表格，不启动模型，也不改写源文件。

选择“基础图表…”后，可从当前已加载表格选择完整数据，勾选字段并打开可用图表。加载表格支持数值直方图、类别计数、数值散点图和相关性图。完成单任务后，“绘制结果图…”还可选择本次 session 的 train、validation 或已成功测试分区；批量窗口的“绘制结果图…”可从已完成任务选择对应分区。test 仅在本次最终测试成功并通过缓存/回执核验后可用；每张图只使用一个来源和一个分区。

结果缓存会列出原始特征、目标列和模型实际生成的输出。根据所选字段和任务类型，选择器会提供真实类别与预测类别、回归真实值/预测值、回归残差、已有坐标上的聚类结果、已有降维坐标散点图或 HMM 隐藏状态与后验概率图。HMM 状态是模型潜在状态，不是真实标签；使用时间排序的序列图按 UTC 时间显示，未配置时间列时按行/序列顺序显示。图窗非模态，关闭前可分别另存当前 PNG 或 SVG；图注列出分区总行数、有效行数和排除行数。

结果区首次打开时默认显示“图表”页；首次可用结果缓存刷新时会自动选中该页一次。用户手动切换标签后，后续缓存刷新会保留当前选择。没有可绘制缓存时，页面会显示原因，不会为画图重新训练或读取最终测试集。

较早版本生成的单任务 session 若缺少自己的绘图完整性清单，其结果图来源不可用。批量 job 的图表分别核验 winner session、final-session 和测试回执；记录缺少清单或回执时，对应分区图表不可用。旧配置、job、session 或模型文件能否载入取决于当前版本、依赖、数据与配置哈希和持久回执，不保证跨版本恢复。遇到不兼容记录时，应保留原环境和文件，并在对应版本中查看；不要创建新 job 来重复使用已查看过的测试集。绘图入口不会自动补写清单、重读源表、重新训练或执行最终测试；重新加载原表后仍可从“基础图表…”绘制完整数据的 EDA 图。

## 配置并查看验证结果

1. 在“任务、模型与参数”中选择分类、回归、聚类、降维、异常检测或“序列建模 / HMM”，再选择对应模型。N01/N02 是神经网络分类/回归；N04/N06/N07/N08/N09 是 LSTM、GRU、CNN、TCN 和 Transformer 窗口回归。
2. 调整显示的常用参数；“高级参数”必须是 JSON 对象，且参数名和值必须被所选模型支持。模型参数和依赖见[模型与参数索引](model-index.md)。例如 SVC 概率输出需设置 `probability=true`；LOF 对新数据预测需设置 `novelty=true`。如果缺少 HMM 或深度模型依赖，工作台会显示需要安装的 extra。
3. 在“预处理与数据划分”中可选启用训练前降维并设置方法和输出维数，默认关闭。可选 PCA、TruncatedSVD、FastICA、GaussianRandomProjection 或 KernelPCA。降维器只在训练分区拟合，验证、测试和新数据只应用已拟合的变换；输出维数必须小于预处理后的特征数，并满足所选算法的拟合行数和数据秩限制。独立降维任务、HMM/窗口回归模型、MultinomialNB/ComplementNB 和 CategoricalNB 不支持此选项。
4. 可调整随机种子，默认值为 42。普通表格分类/回归可使用留出法或 GUI 中的独立 K 折交叉验证（K 为 2–10，默认 5）。两者均保留独立的 20% 最终测试集：留出法按 60/20/20 划分，K 折在其余 80% 开发集上比较模型。分类 K 折要求开发集每类样本数不少于 K，测试集也要能分层；条件不足时请减小 K、补充数据或改用留出法，程序不会静默切换。每折的预处理只在该折训练行拟合，开发集每行恰有一次 OOF 预测；冻结选择后才在完整开发集重拟合并执行一次最终测试。独立 K 折下 `max_fits` 按候选计数，但每个候选仍在 K 个折上训练；附加的 `evaluation` 折验证则按每候选一次主拟合加折数计真实拟合预算。K 折均值和标准差是预测性能摘要，不是独立样本推断检验。N01/N02、HMM、窗口序列和传统时序预测模型不支持独立 K 折；分组/时间折验证须通过匹配的 `evaluation` 与外层划分配置，详情见[模型、指标与验证方式](model-expansion.md)。
5. 可选填“结果目录”，路径应不存在或为空。点“训练并验证”后，工作台在后台进程中拟合预处理和模型，只展示训练与验证结果。预处理只在训练分区拟合。
6. 查看默认打开的“图表”页，或切换到“指标”“阶段日志”和“导出与审计”。在结果比较流程中点击“导出所选格式”会先弹出对话框，选择 CSV/XLSX/JSON/HTML、逐样本结果、模型文件、比较图 PNG 和保存目录；取消不会写文件，确认后才导出并显示目标位置。K 折结果分别列出折均值、折间标准差、OOF 汇总和（有成功回执时）最终测试；逐样本 CSV 只含 OOF 与最终测试，不包含开发集重拟合行。留出法仍列验证集与最终测试。修改数据、任务、模型或参数会使当前结果失效，需要重新训练与验证。

验证集指标用于检查当前模型；最终测试集尚未用于评分。

### 单任务界面中的序列设置

选择 H01/H02/H03 或 N04/N06/N07/N08/N09 后，“任务、模型与参数”区域会显示“序列配置 JSON”编辑器。留空或输入 `{}` 时，程序按 CSV 当前行顺序处理单一序列；窗口回归默认 `window=10`、`horizon=1`。按设备、病人等字段分组并按时间排序时，在这个编辑器中填 JSON 对象，例如：

```json
{
  "group_column": "device_id",
  "time_column": "timestamp",
  "order_mode": "time",
  "window": 10,
  "horizon": 1
}
```

HMM 可在同一对象中加入 `"observation_columns": ["value"]`，指定 HMM 观测列。配置中的分组列和时间列会从特征选择中自动取消勾选并禁用；监督任务的目标列也不能作为特征。JSON 必须是有效对象。时间列需要配合 `order_mode: "time"`，具体字段、排序与切分规则见[序列建模指南](sequence-guide.md)和[深度学习指南](deep-learning-guide.md)。

序列模型训练后，结果区的“序列划分”页显示实际 train、validation、test 三份的源行数、组数、窗口数及各自比例；比例按三份合计计算。按组划分时，各份行数可能与 60/20/20 略有差别，应查看这里的实际结果。单任务深度模型的“训练曲线”页绘制实际 skorch history 中逐 epoch 的训练损失与可用的验证损失。批量队列中选中已完成任务后，任务详情也会显示其序列划分统计；深度模型任务可查看 validation winner 的训练/验证曲线，最终在训练集与验证集合并重拟合后则显示实际训练损失且不计算验证损失。HMM 不产生 skorch 深度模型训练曲线。

### 重载序列模型并推理 CSV

序列设置会随模型包保存。回到“已加载模型的推理”，选择训练完成时导出的 `model.joblib` 并点“加载模型”，再选择新 CSV，点“运行推理并导出 CSV”。使用了分组/时间排序的模型时，新 CSV 需包含保存配置要求的分组列和时间列；这些是结构字段，不会被当作数值特征。界面按模型包中的序列配置排序、分组和生成窗口，不要求用户再编辑 Python 配置或批量搜索 JSON。

H01/H02/H03 的输出每条输入源行一行，包含零起始 `source_row_position`、`source_index`、`group_id`、`hidden_state` 和各状态的 `posterior_i` 列。N04/N06/N07/N08/N09 的输出每个有效预测目标一行：`source_row_position` 指向目标行，`window_source_row_positions` 和 `window_source_indexes` 是 JSON 数组，记录该预测使用的窗口源行位置与原索引；输出也包含 `group_id` 和 `prediction`。这些位置对应当前新 CSV，而不是训练文件。默认窗口会在每个组内独立构造，窗口不会跨组；`window` 与 `horizon` 的目标行关系见[序列建模指南](sequence-guide.md)。

## 冻结并进行一次最终测试

确认特征、目标、任务、模型和参数后，点“锁定并执行最终测试”。此操作冻结已拟合配置，然后对留出的测试分区做一次最终评估。按钮不会因为重复点击而创建第二次测试；测试失败或中断后保留失败记录，不要创建新任务重测同一测试集。需要新一轮评估时，应依据研究计划使用新的独立数据。

如果设置了结果目录，完成后会写入 `config.json`、`metrics.json`、`metrics.csv`、`metrics.xlsx`、`results.csv`、`results.xlsx`、`model.joblib` 和 `model_manifest.json`。可在“导出与审计”查看/打开这些文件，或导出选中文件的副本。逐行结果包含实际支持的训练、验证或测试预测/变换内容；不支持新行操作的算法不会伪造结果。

## 重载模型与新数据推理

在“已加载模型的推理”中选择 `model.joblib` 并点“加载模型”。也可在 Python API 中将模型文件或含 `model.joblib` 的目录传给 `load_model`。界面会读取拟合模型的实际能力，只启用支持的操作。选择新的表格文件和可选工作表后，点“运行推理并导出 CSV”；默认输出为输入文件旁的新 CSV，已存在的目标路径不会被覆盖。

新数据必须包含训练时使用的特征列。表格列名不齐、文件无法读取或模型不支持所选操作时，界面会显示错误。分类/回归模型通常提供 `predict`；聚类、降维和异常模型的可用方法因 estimator 和参数而异。训练时未设 `novelty=True` 的 LOF 不支持新样本预测；默认未设 `probability=True` 的 SVC 不开放概率输出。

## 批量搜索与队列恢复

主窗口底部的“批量搜索队列”按钮会打开独立队列窗口。如果当前单任务配置有效，窗口会预填当前数据、任务、模型、参数和种子；也可添加多个数据文件或直接编辑 JSON。每个数据行可列出多个兼容模型，搜索空间按模型分别设定。详细字段格式与目标配置见[批量搜索指南](batch-guide.md)。

Grid、随机、TPE、遗传和退火方法共享类型化参数空间。新任务默认每个组合最多 10 个搜索预算单位、30 个 proposals 和 10 分钟活动时间，运行 1 个 worker（每个 worker 固定使用一个数值线程）；界面允许提高这些值，最多 50 个预算单位、250 个 proposals、20 分钟和 2 个 worker。预算单位如何对应模型拟合取决于交叉验证路径，见上文。更多候选、proposals 或时限通常需要更多 CPU 时间，但不保证结果更好；增加 worker 会同时运行更多算法，增加 CPU 和内存占用。任一预算上限先到即停止。`fields` 为空的固定参数组合可选择 Grid，形成一次候选与一次搜索评估；随机、TPE、遗传或退火需要至少一个搜索字段。TPE 需要 Optuna，遗传搜索需要 pymoo；缺少依赖时界面会显示对应安装信息。

预检检查数据、列、模型/任务兼容性和搜索空间后，队列记录写入批次目录的 `history.sqlite3`，模型快照与拟合回执保存在独立 job 子目录。暂停、恢复、取消和读取历史都针对所选 job；搜索期间不会读取测试分区。恢复历史前会校验当前数据、配置、快照和回执；跨版本工件不保证兼容。校验通过的已完成历史只回填批量设置并显示已有结果，不会自动启动搜索、重新拟合或执行最终测试。如需开始新搜索，请检查配置后点击“预检并启动队列”。恢复未完成任务时，只继续明确选择且通过校验的待完成工作。只有 `completed` job 才能冻结验证 winner；最终化会用训练+验证数据重拟合（80%），随后对测试分区评估一次。最终化结果与一次性测试许可会持久记录；导出内容保存在批次目录的 `exports/<job_id>` 下。不要新建 job 重测已查看过的测试集。

## 适用性与结果边界

模型目录展示的是软件当前提供的条目；各模型对数据类型、样本规模、参数、依赖和新样本操作的要求可能不同。运行环境检查可以说明依赖是否可用，不代表模型适用于某个研究问题。预测分数用于预测性能评价；统计推断应按研究单位、研究问题和预先声明的分析计划单独完成。
