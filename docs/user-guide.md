# 用户指南

完整工作流程见[整体指南](overall-guide.md)；主窗口顶部“整体指南”按钮、帮助菜单或 F1 可打开应用内离线阅读窗口，支持章节跳转和搜索。

Windows EXE：解压完整分发 ZIP，双击 `PYML-Workbench.exe`；保留后台 EXE 与 `_internal`，无需安装 Python。详见 [EXE 指南](exe-guide.md)。

本指南介绍 PY-ML 单任务工作台的使用方法。它使用本机 CSV/Excel 表格和一个活动模型；批量搜索队列另见[批量搜索指南](batch-guide.md)。模型目录包括 71 个传统 estimator、3 个 HMM 和 4 个深度模型。HMM/深度模型分别需要 `sequence`/`deep` 可选依赖；分组时间序列与窗口参数见[序列建模指南](sequence-guide.md)和[深度学习指南](deep-learning-guide.md)。

本指南对应 **0.4.2（2026-10-02）**。图表只使用当前完整表格或通过主应用核验的任务缓存；旧缓存缺少绘图清单时不会自动重训或执行测试。

## 启动

在项目根目录完成依赖同步后，双击 `run_pyml_workbench.bat`，或在 PowerShell 运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pyml_workbench
```

启动器使用已有 `.venv`；如提示缺少虚拟环境，请先按 [README 安装步骤](../README.md#安装与启动)同步，不要把源码目录添加为 editable 安装。

## 日志、参数配置与最近文件

### 错误详情与日志目录

右侧“阶段日志”显示当前任务的进度；窗口顶部的“复制错误详情”会把错误 ID 和 traceback 复制到剪贴板，反馈问题时可一并提供。应用诊断日志默认保存在 Windows 的 `%LOCALAPPDATA%\PyMLWorkbench\logs`。在“文件”菜单选择“选择日志目录…”可立即切换后续日志的保存位置；“恢复默认日志目录”会切回默认位置，已经写入旧目录的日志不会搬到新目录。若日志不可用，窗口会显示提示，工作流程仍可继续。

选择“文件”→“导出诊断包…”后，可导出“当前界面会话”，也可选择“按错误编号”并输入此前复制或保存的 32 位 `error_id`。接着选择 ZIP 的保存位置。导出内容按字段 allowlist 收集并脱敏，最大 20 MiB；程序只在本机创建文件，不会上传。任一步骤取消都不会创建 ZIP；无效或找不到的编号会显示提示；已有目标文件会受到保护，不会被覆盖。导出不会更改实验结果或日志目录设置。

### 保存和加载参数配置

在“文件”菜单选择“保存参数配置 JSON…”可保存当前任务、模型、数据文件路径、列选择、参数、随机种子、序列设置和结果目录。该文件保存配置与路径，不复制数据集或模型结果，也不会启动训练。请将 JSON 保存到独立位置；程序会拒绝用配置文件覆盖数据源或写入结果目录。

选择“加载参数配置 JSON…”后，配置会经过校验并回填单任务界面。若配置中的数据文件仍存在，工作台会加载该文件以恢复预览和列选择；若文件不可用，会保留配置并提示重新选择数据源。加载配置不会启动拟合、批量搜索或最终测试，也不能在后台任务运行期间进行。恢复设置后请检查数据与参数，再明确启动后续流程。

### 最近文件

成功加载的表格路径会按最近使用顺序保存在“文件”→“最近文件”中，最多记录 10 个路径。选择菜单项会重新加载对应文件；源文件已不存在时，菜单会标记并禁用该项。选择“清除最近文件记录”只会清除记忆的路径，不会删除表格或日志。

最近文件和日志目录属于应用偏好设置，与单次实验参数配置分开保存。Windows 默认偏好文件位于 `%APPDATA%\PY-ML\preferences.json`。

## 导入与预览

1. 在“数据与列选择”中点“选择文件”，选择 `.csv`、`.xlsx` 或 `.xls`，再点“加载预览”。预览会读取表格和少量示例行，不写回源文件。
2. Excel 文件可在“工作表”中选择工作表。CSV 没有工作表选择。
3. 勾选要用作输入的特征列。分类和回归需要在“目标列”选择标签/数值目标；聚类、降维和异常检测不使用目标列。目标列不能同时作为特征。
4. 检查预览、列类型和缺失情况。监督任务的目标值不能缺失；无效路径、重复列或不支持的文件格式会显示错误，修正输入后重新加载。

数据读取与预览不修改原表。训练结果应保存到单独的新目录；程序会拒绝覆盖输入文件或已有产物。

## 数据概况与基础图表

加载表格后，在主窗口“分析”菜单中选择“数据概况…”，查看完整数据的行列数、逐列类型与缺失数，以及 pandas `describe(include="all")` 描述统计。概况基于当前内存中的已加载表格，不启动模型，也不改写源文件。

选择“基础图表…”后，可从当前已加载表格选择完整数据，勾选字段并打开可用图表。加载表格支持数值直方图、类别计数、数值散点图和相关性图。完成单任务后，“绘制结果图…”还可选择本次 session 的 train、validation 或已成功测试分区；批量窗口的“绘制结果图…”可从已完成任务选择对应分区。test 仅在本次最终测试成功并通过缓存/回执核验后可用；每张图只使用一个来源和一个分区。

结果缓存会列出原始特征、目标列和模型实际生成的输出。根据所选字段和任务类型，选择器会提供真实类别与预测类别、回归真实值/预测值、回归残差、已有坐标上的聚类结果、已有降维坐标散点图或 HMM 隐藏状态与后验概率图。HMM 状态是模型潜在状态，不是真实标签；使用时间排序的序列图按 UTC 时间显示，未配置时间列时按行/序列顺序显示。图窗非模态，关闭前可分别另存当前 PNG 或 SVG；图注列出分区总行数、有效行数和排除行数。

此前版本生成的单任务 session 若缺少自己的绘图完整性清单，其结果图来源不可用。批量 job 的结果来源分开核验：winner session 清单用于 train/validation；仅有数据快照收据不足以核验缓存预测行，因此 winner 清单缺失时该 job 的结果图均不可用。若 winner 清单有效但旧 final-session 缺少独立清单，train/validation 仍可从已核验的 winner session 绘制，test 图不可用。绘图入口不会自动补写清单、重读源表、重新训练或执行最终测试；需要这些缓存结果图时，请按正常流程手动创建新会话或新 job。旧任务已有的查看和导出功能保持可用；重新加载原表后仍可从“基础图表…”绘制完整数据的 EDA 图。

## 配置并查看验证结果

1. 在“任务、模型与参数”中选择分类、回归、聚类、降维、异常检测或“序列建模 / HMM”，再选择对应模型。N01/N02 是神经网络分类/回归；N04/N06 是 LSTM/GRU 窗口回归。
2. 调整显示的常用参数；“高级参数”必须是 JSON 对象，且参数名和值必须被所选模型支持。模型参数和依赖见[模型与参数索引](model-index.md)。例如 SVC 概率输出需设置 `probability=true`；LOF 对新数据预测需设置 `novelty=true`。如果缺少 HMM 或深度模型依赖，工作台会显示需要安装的 extra。
3. 可调整随机种子，默认值为 42。工作流使用固定的 60/20/20 训练/验证/测试划分；分类任务分层抽样，每个类别至少需要 3 行，全部任务至少需要 10 行。HMM、LSTM 和 GRU 会按组拆分完整序列，避免同一组落入不同分区。
4. 可选填“结果目录”，路径应不存在或为空。点“训练并验证”后，工作台在后台进程中拟合预处理和模型，只展示训练与验证结果。预处理只在训练分区拟合。
5. 查看“指标”“阶段日志”及“导出与审计”中的结果。修改数据、任务、模型或参数会使当前结果失效，需要重新训练与验证。

验证集指标用于检查当前模型；最终测试集尚未用于评分。

### 单任务界面中的序列设置

选择 H01/H02/H03、N04 或 N06 后，“任务、模型与参数”区域会显示“序列配置 JSON”编辑器。留空或输入 `{}` 时，程序按 CSV 当前行顺序处理单一序列；窗口回归默认 `window=10`、`horizon=1`。按设备、病人等字段分组并按时间排序时，在这个编辑器中填 JSON 对象，例如：

```json
{
  "group_column": "device_id",
  "time_column": "timestamp",
  "order_mode": "time",
  "window": 10,
  "horizon": 1
}
```

HMM 可在同一对象中加入 `"observation_columns": ["value"]`，指定 HMM 观测列。配置中的分组列和时间列会从特征选择中自动取消勾选并禁用；监督任务的目标列也不能作为特征。JSON 必须是有效对象。时间列需要配合 `order_mode: "time"`，具体字段、排序与切分规则见[序列建模指南](sequence-guide.md)和[深度学习指南](deep-learning-guide.md)。

序列模型训练后，结果区的“序列划分”页显示实际 train、validation、test 三份的源行数、组数、窗口数及各自比例；比例按三份合计计算。按组划分时，各份行数可能与 60/20/20 略有差别，应查看这里的实际结果。单任务深度模型的“训练曲线”页绘制实际 skorch history 中逐 epoch 的训练损失与可用的验证损失。批量队列中选中已完成任务后，任务详情也会显示其序列划分统计；深度模型任务可查看 validation winner 的训练/验证曲线，最终在训练集与验证集合并重拟合后则显示实际训练损失且不计算验证损失。HMM 不产生 skorch 深度模型训练曲线。

### 重载序列模型并推理 CSV

序列设置会随模型包保存。回到“已加载模型的推理”，选择训练完成时导出的 `model.joblib` 并点“加载模型”，再选择新 CSV，点“运行推理并导出 CSV”。使用了分组/时间排序的模型时，新 CSV 需包含保存配置要求的分组列和时间列；这些是结构字段，不会被当作数值特征。界面按模型包中的序列配置排序、分组和生成窗口，不要求用户再编辑 Python 配置或批量搜索 JSON。

H01/H02/H03 的输出每条输入源行一行，包含零起始 `source_row_position`、`source_index`、`group_id`、`hidden_state` 和各状态的 `posterior_i` 列。N04/N06 的输出每个有效预测目标一行：`source_row_position` 指向目标行，`window_source_row_positions` 和 `window_source_indexes` 是 JSON 数组，记录该预测使用的窗口源行位置与原索引；输出也包含 `group_id` 和 `prediction`。这些位置对应当前新 CSV，而不是训练文件。默认窗口会在每个组内独立构造，窗口不会跨组；`window` 与 `horizon` 的目标行关系见[序列建模指南](sequence-guide.md)。

## 冻结并进行一次最终测试

确认特征、目标、任务、模型和参数后，点“锁定并执行最终测试”。此操作冻结已拟合配置，然后对留出的测试分区做一次最终评估。按钮不会因为重复点击而创建第二次测试；任务中断或测试失败时，当前会话不能悄悄重测，应修正配置并重新训练。

如果设置了结果目录，完成后会写入 `config.json`、`metrics.json`、`metrics.csv`、`metrics.xlsx`、`results.csv`、`results.xlsx`、`model.joblib` 和 `model_manifest.json`。可在“导出与审计”查看/打开这些文件，或导出选中文件的副本。逐行结果包含实际支持的训练、验证或测试预测/变换内容；不支持新行操作的算法不会伪造结果。

## 重载模型与新数据推理

在“已加载模型的推理”中选择 `model.joblib` 并点“加载模型”。也可在 Python API 中将模型文件或含 `model.joblib` 的目录传给 `load_model`。界面会读取拟合模型的实际能力，只启用支持的操作。选择新的表格文件和可选工作表后，点“运行推理并导出 CSV”；默认输出为输入文件旁的新 CSV，已存在的目标路径不会被覆盖。

新数据必须包含训练时使用的特征列。表格列名不齐、文件无法读取或模型不支持所选操作时，界面会显示错误。分类/回归模型通常提供 `predict`；聚类、降维和异常模型的可用方法因 estimator 和参数而异。训练时未设 `novelty=True` 的 LOF 不支持新样本预测；默认未设 `probability=True` 的 SVC 不开放概率输出。

## 批量搜索与队列恢复

主窗口顶部的“批量搜索队列”按钮会打开独立队列窗口。如果当前单任务配置有效，窗口会预填当前数据、任务、模型、参数和种子；也可添加多个数据文件或直接编辑 JSON。每个数据行可列出多个兼容模型，搜索空间按模型分别设定。详细字段格式与目标配置见[批量搜索指南](batch-guide.md)。

Grid、随机、TPE、遗传和退火方法共享类型化参数空间。每个组合可设置最多 50 次真实搜索拟合、250 个 proposals 和 20 分钟活动时间；队列同时运行 1 或 2 个 worker，每个 worker 固定使用一个数值线程。`fields` 为空的固定参数组合可选择 Grid，形成一次候选与一次真实拟合；随机、TPE、遗传或退火需要至少一个搜索字段。TPE 需要 Optuna，遗传搜索需要 pymoo；缺少依赖时界面会显示对应的安装命令。基础依赖仍支持 Grid、随机和退火。

预检检查数据、列、模型/任务兼容性和搜索空间后，队列记录写入批次目录的 `history.sqlite3`，模型快照与拟合回执保存在独立 job 子目录。暂停、恢复、取消和读取历史都针对所选 job；搜索期间不会读取测试分区。只有 completed job 才能冻结验证 winner；最终化会用训练+验证数据重拟合（80%），随后对测试分区评估一次。最终化结果与一次性测试许可会持久记录；导出内容保存在批次目录的 `exports/<job_id>` 下。

## 验证覆盖范围

本期样例和格式验证使用合成数据；CSV 与 XLSX 已实际验证，XLS 尚无实际样本验证记录。模型 smoke 结果证明的是适用任务下能执行，不代表模型质量或适用于特定用户数据。详见 [`version.md`](../version.md) 与第三方组件说明。
